# Kiro proxy landscape

**Research date:** 2026-10-02  
**Scope:** Maintained public GitHub projects that translate Kiro / Amazon Q Developer / CodeWhisperer into OpenAI or Anthropic-compatible APIs, plus multi-provider routers with a Kiro adapter. I reviewed repository metadata, README/source files, and recent issues, pull requests, and commits (approximately 2026-04-02 through 2026-10-02). Repository metadata (stars, language, pushed date) is from the GitHub REST API on the research date. “Has” means the linked primary source documents or implements the behavior; it is not a claim that every deployment has the feature enabled.

## Executive summary

The closest comparators are [jwadow/kiro-gateway](https://github.com/jwadow/kiro-gateway), [hank9999/kiro.rs](https://github.com/hank9999/kiro.rs), [Quorinex/Kiro-Go](https://github.com/Quorinex/Kiro-Go), and [nopperabbo/kiroxy](https://github.com/nopperabbo/kiroxy). Their common baseline is Anthropic Messages translation, SSE, token refresh, tools, thinking, and multi-account failover. The most useful evidence is not feature marketing but recent compatibility fixes: Opus-class Kiro responses can emit text-wrapped tool calls ([pi-provider-kiro commit](https://github.com/mikeyobrien/pi-provider-kiro/commit/c7a7ea548b11cd704ca609aef237e04febce7373)); Kiro clients need identity-keyed fragmented tool assembly and incomplete-EOF handling ([OpenCodex stream adapter](https://github.com/lidge-jun/opencodex/blob/main/src/adapters/kiro/stream.ts), [Kiro-Go parser](https://github.com/Quorinex/Kiro-Go/blob/main/proxy/kiro.go#L690-L950)); and a recent Kiro gateway PR recommends learning previously unadvertised models after a successful request ([kiro-gateway #285](https://github.com/jwadow/kiro-gateway/pull/285)).

This repository already has unusually strong low-level Kiro handling: CRC-validated EventStream decoding, identity-keyed tool fragments, bounded pre-output retry, catalog-driven native reasoning, payload/image guards, model-scoped empty-response cooldown, model/context normalization, MCP web search, and refresh coalescing. The remaining high-impact gaps are mostly Anthropic-surface fidelity and model-specific behavior: beta-header/cache semantics, signed/empty native thinking preservation, explicit 529/overloaded error mapping, and richer continuation/session identity. The repository also has no document/PDF input path; current image handling is explicit and base64-only.

## Recent compatibility signals

### Opus, thinking, and model discovery

* [kiro.rs PR #201](https://github.com/hank9999/kiro.rs/pull/201) treats Opus 5.5 as an alias-ordering problem: `opus-5-5` must match before a broad `opus-5` branch, and both ordinary and thinking IDs need 1M context metadata.
* [9router commit a99cf57](https://github.com/decolua/9router/commit/a99cf57239ff778b61e434c2786009d5ed1c412c) resolves newer Sonnet models to adaptive thinking instead of forging disabled-thinking placeholders. This aligns with the independent Opus 5.5 evidence in [Hermes #120069](https://github.com/NousResearch/hermes-agent/issues/120069), where `thinking.type=disabled` produced a 400 and adaptive thinking plus `output_config.effort` was required.
* [pi-provider-kiro models.ts](https://raw.githubusercontent.com/mikeyobrien/pi-provider-kiro/main/src/models.ts) and [effort.ts](https://raw.githubusercontent.com/mikeyobrien/pi-provider-kiro/main/src/effort.ts) derive effort fields from Kiro's `additionalModelRequestFieldsSchema`; this is safer than a hard-coded model-name list. [LiteLLM #42871](https://github.com/BerriAI/litellm/issues/42871) separately reports Opus 5.5 signature-only thinking (empty text plus signature) being lost by a streaming adapter. This is not proof of the private Kiro wire shape, but it is a strong reason to preserve signed/empty reasoning blocks.
* [kiro-gateway PR #285](https://github.com/jwadow/kiro-gateway/pull/285) proposes registering a model after its first successful request when the runtime has no model-list endpoint. This avoids making `/v1/models` stale every time Kiro ships a model.

### Tool calling and stream termination

* [pi-provider-kiro commit c7a7ea5](https://github.com/mikeyobrien/pi-provider-kiro/commit/c7a7ea548b11cd704ca609aef237e04febce7373) is the clearest recent Opus-specific compatibility report: tool calls sometimes arrive as text tags rather than native frames, with different field spellings and array wrappers. It recovered calls at one emit seam and deliberately avoided ambiguous aliases.
* [OmniRoute #2446](https://github.com/diegosouzapw/OmniRoute/issues/2446) shows that a translated follow-up can fail with 400 when structured tool results become empty text, status is hard-coded, or generated assistant/tool IDs do not match. [OmniRoute #14668](https://github.com/diegosouzapw/OmniRoute/issues/14668) shows that only accepting string deltas drops object/snapshot inputs and yields `{}`/empty arguments.
* [OpenCodex Kiro stream state](https://github.com/lidge-jun/opencodex/blob/main/src/adapters/kiro/stream.ts) and [Kiro-Go](https://github.com/Quorinex/Kiro-Go/blob/main/proxy/kiro.go#L690-L950) both retain tool state by ID, tolerate partial frames, and refuse to deliver incomplete calls at EOF. [OpenCodex #519](https://github.com/lidge-jun/opencodex/issues/519) documents heartbeat-only streams that close after about 60 seconds; replay was safe only because no bytes had reached the client.
* [Kiro-Go PR #161](https://github.com/Quorinex/Kiro-Go/pull/161) accepts a text-only CLI EOF without a stop reason. This is a client-specific leniency, not a reason to turn a metadata-only Kiro stream into a successful answer.

### Authentication, quotas, and upstream acceptance

* [pi-provider-kiro commit d1623c8](https://github.com/mikeyobrien/pi-provider-kiro/commit/d1623c81c1579a68c8a12f3211ed635f8ae32a0d) identifies a refresh race: a provider refreshed a token for one call, discarded it, and seeded the next call from a stale host token. Its accessor design writes changed credentials back and supports proactive refresh.
* [Kiro-Go PR #164](https://github.com/Quorinex/Kiro-Go/pull/164) records a real upstream contract change: `ListAvailableProfiles` started rejecting `maxResults`, breaking profile resolution and usage refresh. The fix sends `{}` or only `nextToken`.
* The local Kiro-compatible implementations consistently send a Kiro IDE version and fingerprint. [kiro-proxy `util.KiroHeaders`](internal/util/util.go:87-104) sends `User-Agent`, `x-amz-user-agent`, `KiroIDE-<version>-<fingerprint>`, and Kiro-specific headers; [Colin's README](https://github.com/Colin3191/kiro-proxy/blob/main/README_EN.md) also documents a configurable Kiro version. [kiro-gateway #284](https://github.com/jwadow/kiro-gateway/pull/284) reports that some Claude-family IDs work only from a non-CN IP, so location/proxy is an acceptance condition, not merely a convenience.
* [9router commit a99cf57](https://github.com/decolua/9router/commit/a99cf57239ff778b61e434c2786009d5ed1c412c) explicitly avoids refresh-token reuse during auto-ping. That matters for long-lived Claude Code processes, where a background health request can otherwise consume or invalidate the token needed by the foreground stream.

### Anthropic surface, caching, documents, and web search

The inspected projects primarily implement text, image, tool, thinking, and web-search translation. I found no Kiro-specific primary source in this set proving full PDF/document forwarding. `kiro.rs PR #199` demonstrates image preservation inside `tool_result`; [Colin's README](https://github.com/Colin3191/kiro-proxy/blob/main/README_EN.md) documents data-URL images; and the Kiro adapters generally convert images into Kiro image entries rather than passing Anthropic document blocks unchanged. Multi-provider routers advertise prompt/cache accounting and MCP, but those are not evidence that Kiro accepts Anthropic `document` blocks.

## Ranked shortlist

1. **Preserve native signed/empty thinking instead of replacing it with fake reasoning.** The direct Opus 5.5 streaming failure is documented in [LiteLLM #42871](https://github.com/BerriAI/litellm/issues/42871), while this checkout currently documents fake signatures at [`responses.go`](internal/api/anthropic/responses.go:33-38). This is the most model-specific fix for Opus reliability and continuation.
2. **Add text-emitted tool-call recovery at the stream boundary.** [pi-provider-kiro commit c7a7ea5](https://github.com/mikeyobrien/pi-provider-kiro/commit/c7a7ea548b11cd704ca609aef237e04febce7373) reports Opus-class `<tool_use>`/`<tool_call>` dialects that otherwise become narrated no-ops. Keep aliases narrow and reject ambiguous names.
3. **Make model discovery self-healing after successful requests.** [kiro-gateway #285](https://github.com/jwadow/kiro-gateway/pull/285) gives a concrete no-probing design. This complements the existing catalog and prevents newly released Opus IDs from being invisible to Claude Code.
4. **Implement explicit Anthropic overloaded/529 error fidelity.** [OpenCodex #6438](https://github.com/lidge-jun/opencodex/pull/6438) motivates preserving useful upstream messages; the local transport retries 5xx but has no explicit `529`/`overloaded` mapping ([`upstream/client.go`](internal/upstream/client.go:84-99), [`streaming.go`](internal/api/anthropic/streaming.go:127-132)). Preserve status, error type, and retryability without masking Kiro reasons.
5. **Honor Anthropic beta/cache request semantics and usage fields.** [pi-provider-kiro usage/cache documentation](https://github.com/mikeyobrien/pi-provider-kiro#estimated-usage) and [9router's cache/thinking changes](https://github.com/decolua/9router/commit/a99cf57239ff778b61e434c2786009d5ed1c412c) motivate a deliberate `cache_control`/beta policy. Current code forwards reported counters but grep found no request-side `cache_control` or `anthropic-beta` support.
6. **Bound heartbeat/keepalive completion waits while preserving retry safety.** [OpenCodex #519](https://github.com/lidge-jun/opencodex/issues/519) and [9router's 3-second watchdog](https://github.com/decolua/9router/commit/fbcaa2828c0775503899c22df5e6bb04790758ec) show the failure mode. Keep the existing first-token retry, add a post-finish watchdog, and never replay after client-visible output.
7. **Add explicit conversation/continuation affinity where the client supplies it.** [OmniRoute #2446](https://github.com/diegosouzapw/OmniRoute/issues/2446) shows how mismatched generated IDs break tool follow-ups; [OpenCodex's thread account affinity](https://github.com/lidge-jun/opencodex) shows the operational value of session identity. The local deterministic `conversationId` is useful but not equivalent to an explicit continuation contract.
8. **Adopt quota/latency/load-aware account selection without weakening model cooldowns.** [Kiro-GoPlus README](https://github.com/ducphamzyr/Kiro-GoPlus#features) and [Kiro-Go README](https://github.com/Quorinex/Kiro-Go#features) motivate selection by model support, quota, latency, reliability, and load. The local manager already has persisted circuit breakers and model cooldowns; add selection signals only where they can be derived reliably.
